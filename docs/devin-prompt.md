*Скопируйте текст ниже в Devin целиком. Предполагается машина с NVIDIA GPU (≥8 ГБ VRAM),
установленной Ollama и доступом к репозиторию.*

## Контекст

Ты работаешь с репозиторием `botkin` — медицинская система распознавания (OCR/VLM)
лабораторных результатов и рецептов: Python, FastAPI, Telegram-бот, Ollama (qwen3-vl),
pymupdf, SQLite. Рабочая ветка — `refactor/web-cabinet-quality` (НЕ master).

Проект ведёт публичный технический дневник для статьи на Хабре и доклада:
`habr/lab-results-journal.md`. Твоя главная задача — **прогнать бенчмарк моделей на GPU
и дописать в дневник фактуру с реальными числами**.

## Установка и проверка окружения

```bash
git clone <repo-url> && cd botkin
git checkout refactor/web-cabinet-quality
python -m venv .venv && .venv/bin/pip install -e ".[dev]" 2>/dev/null || .venv/bin/pip install -e .

# базовая проверка (без LLM): должно быть 367+ passed
.venv/bin/python -m pytest -m "not llm" -q
.venv/bin/ruff check src tests

# Ollama и GPU
ollama --version && nvidia-smi --query-gpu=name,memory.total --format=csv
ollama pull qwen3-vl:8b-instruct
ollama pull glm-ocr
ollama pull qwen2.5vl:7b
```

## Задача 1 — бенчмарк «ожидания vs реальность» (главная)

```bash
.venv/bin/python scripts/bench/bench_expectations.py --pull
```

Скрипт прогоняет e2e-корпус (34 реальных документа с эталонной разметкой в
`tests/fixtures/documents/samples/`) на трёх моделях и пишет:
- `scripts/bench/bench_expectations_report.md` — таблица «ожидание (публичные бенчи) vs
  реальность (наш корпус)»;
- `scripts/bench/bench_expectations_results.json` — сырые числа.

Прогон длится десятки минут на модель — жди терпеливо, следи за логами
`bench_<model>.log` в корне. Если модель зависает дольше 2 часов — прерви её,
зафиксируй факт и иди дальше.

**После прогона:**
1. Приложи отчёт к результатам работы.
2. Обнови `docs/ocr-models-research-2026-07.md`: в Часть 2 добавь раздел
   «Реальность (замер от <дата>, <GPU>)» с итоговой таблицей из отчёта.
3. Если glm-ocr показал точность ≥ качества qwen3-vl при большей скорости —
   явно отметь это как кандидата на смену модели (но НЕ меняй конфиг сам).

## Задача 2 — фактура для Хабра

Допиши в `habr/lab-results-journal.md` новую итерацию (продолжай нумерацию
`## Итерация N: <заголовок>`) с разделами **Проблема → Диагноз → Решение → Итог**:

- Итерация о прогоне бенчмарка: какие модели, какое железо (nvidia-smi), точная
  таблица результатов, расхождения «ожидание vs реальность» с конкретными числами,
  топ-3 самых показательных провала (имя документа, что ожидалось, что извлеклось —
  бери из `bench_<model>.log`).
- Если во время прогона нашёл баг (модель падает, парсер ломается, таймаут) —
  оформи отдельной итерацией с evidence (дословный вывод, команда воспроизведения).

**Железные правила фактуры (Stop-list проекта):**
- НЕ выдумывай числа, цитаты, названия показателей — только то, что реально
  наблюдалось в прогоне. Сомневаешься — пиши `[не подтверждено]`.
- Все числа копируй из отчёта/логов дословно, с командой воспроизведения.
- Evidence приводи дословно: фрагменты логов, сравнения «до/после».

## Правила работы (обязательны)

- **TDD**: ни строчки прод-кода без падающего теста. Тесты: `.venv/bin/python -m
  pytest -m "not llm"`; линт: `.venv/bin/ruff check src tests`. Перед каждым
  коммитом — полный прогон, коммить только зелёное.
- **Чекпоинты**: после каждого значимого шага дописывай 2–4 строки в
  `.remember/now.md` (что сделано, числа, следующий шаг) — сессия может прерваться.
- **Git**: коммить в `refactor/web-cabinet-quality` осмысленными коммитами
  (`bench:`, `docs:`, `fix:`). **НЕ пушить в master, НЕ мержить, НЕ создавать PR**
  без явного запроса.
- Конфиг моделей — через env (`VLM_MODEL`, `TEXT_MODEL`, `OLLAMA_URL`), не через
  правку `config.json`.
- Не трогай `src/botkin/web/` (фронт) и не меняй схему БД — вне скоупа этой сессии.
