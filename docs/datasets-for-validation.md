# Банки данных для валидации распознавания лабораторных результатов

> Обзор источников для проверки и обучения pipeline botkin (OCR/VLM → извлечение →
> нормализация → матчинг ФСЛИ). Составлено на основе раздела 8 отчёта
> `botkin_research_report.docx` и проверки источников через SearXNG (актуально на 2026-06-05).

## Главный вывод

**Открытых российских банков именно ДОКУМЕНТОВ (PDF/фото бланков с результатами)
практически нет.** Это ключевое ограничение: реальные медицинские документы — персональные
данные, публично не выкладываются. Поэтому стратегия валidation botkin — комбинированная:

1. иноязычные открытые корпуса **изображений** лаб.отчётов — для OCR/VLM/layout-движка
   (структура CBC/биохимии язык-агностична);
2. **полу-синтетический российский корпус** — пустые бланки РФ-лабораторий + значения из
   реестра ФСЛИ → известный ground-truth (основной путь, см. `make_lab_pdf`);
3. российские **структурированные** датасеты — как ground-truth справочник параметров,
   единиц, референсов (для нормализатора, не для OCR);
4. **HITL-сбор** реальных документов пользователей — долгосрочный эталонный набор.

Различай два типа данных: **изображения/PDF документов** (вход для OCR/VLM) и
**структурированные числа** (ground-truth для нормализации/матчинга). Большинство «открытых
медицинских датасетов» — второго типа и НЕ годятся как вход распознавания.

## A. Российские структурированные данные (ground truth, НЕ изображения)

### SibMED Data Clinical Repository — `dataset.ssmu.ru`
- **Что:** первый русскоязычный репозиторий открытых клинических данных (Сибирский ГМУ,
  Томск). 120k+ пациентов клиник СибГМУ с 2022 г. Реляционная БД: таблицы `public.patients`,
  `public.events` (события — JSON), словари `dict_parameter`, `dict_parameter_group`,
  `dict_lab_method`, `dict_lab_dev`, `dict_biomaterial`, `dict_container`, `dict_instrument`,
  `dict_icd10`. Лабораторные результаты — числовые/текстовые, через словари.
- **Доступ:** регистрация в личном кабинете + конструктор запросов (`/personal/build/`).
- **Лицензия:** CC-BY 4.0 (по публикации: Куликов и др., *Бюллетень сибирской медицины*,
  2023;22(2):182-184, doi:10.20538/1682-0363-2023-2-182-184).
- **Пригодность для botkin:** ⭐ эталонный справочник русских названий показателей, единиц,
  биоматериалов, референсов — для проверки нормализатора и ФСЛИ-матчинга.
  ❌ НЕ годится как вход OCR/VLM (нет сканов/PDF бланков).

### Не подходят для лабораторных результатов
- **Смоленский ГМУ** (`dd.smolgmu.ru/dataset`) — ZIP с Я.Диска, но темы: COVID/Эбола,
  микроскопия малярии, рентген пневмонии. Лаб.бланков нет.
- **MosMedData** (Центр диагностики и телемедицины ДЗМ) — КТ/МРТ/рентген, не лаб.отчёты.
- **RuMedBench** (Sber AI Lab, `github.com/sb-ai-lab/MedBench`, arXiv:2201.06499),
  **RuMedNLI** (PhysioNet) — NLP-бенчмарки (QA/NLI/NER) по текстам, не бланки результатов.
- **Сеченовский** (`ai.sechenov.ru/datasets`) — пульсовые волны и пр., не лаб.бланки.

## B. Открытые корпуса ИЗОБРАЖЕНИЙ лаб.отчётов (иноязычные, для OCR/VLM/layout)

Структура китайских/англоязычных бланков идентична российским: 4 блока (время/тип отчёта →
данные пациента → таблица `показатель | результат | единица | референс` → подпись).
Проверяют OCR, layout-парсинг, табличную реконструкцию и анти-галлюцинацию VLM, но **не
русскую терминологию**.

| Датасет | Объём | Источник | Лицензия/доступ |
|---|---|---|---|
| **CMDD** (Chinese Medical Documents Dataset) | 357 изображений лаб.отчётов (сканер + телефон, разные освещения/повороты) | `xuewenyuan.github.io/datasets/cmdd` | открытый |
| **Xue et al. dataset** (статья в *BMC Med Inform Decis Mak*) | 238 de-identified изображений (из 119 файлов) + 153 реальных отчёта PKU1 (**CBC 49**, биохимия 26, ПСА 27, онкомаркеры 12, моча 9, вирусология 7) | PMC10629084 / doi:10.1186/s12911-023-02346-6 | open-source, ethics-approved |
| Medical Lab Report Dataset | изображения мед.отчётов | Kaggle `dikshaasinghhh/bajaj` | Kaggle |
| medocr-vision-dataset | лаб.отчёты для OCR/VLM | HF `naazimsnh02/medocr-vision-dataset` | HF |
| OCR-for-Medical-Laboratory-Reports | код detection+recognition | `github.com/xuewenyuan/OCR-for-Medical-Laboratory-Reports` | код (MIT-подобн.) |

Связанная литература: Xue et al., *Text Detection and Recognition for Images of Medical
Laboratory Reports With a Deep Learning Approach* (IEEE 8941040); tabular extraction из
scanned CBC-отчётов — *J Biomed Inform* S1532046424001539.

## C. Полу-синтетический российский корпус — основной путь ⭐

Пустые **направительные бланки реальных РФ-лабораторий** публично доступны в PDF и дают
реальный layout/шапки/шрифты:

- **ИНВИТРО** — `invitro.ru/doctors/directed_forms/`; пример бланка ОАК: `invitro.by/upload/iblock/936/General_blank.pdf`
- **Ситилаб** — `citilab.ru/enterprise/forms/`
- **CMD** — `cmd-online.ru/vracham/blanki/`
- **KDL** — `kdlmed.ru/doctors/blank/`

**Идея:** взять layout реальных бланков → наполнить значениями/единицами/референсами из
собственного **реестра ФСЛИ** (и словарей SibMED) → рендерить PDF с известным ground-truth.
Это даёт большой размеченный корпус для регресс-метрик (CER, % извлечённых строк, точность
матчинга) с детерминированной проверкой — без зависимости от Ollama.

**Реализация в репозитории:** фикстура `make_lab_pdf` в `tests/conftest.py` — генератор
табличного РФ-бланка (шапка лаборатория/пациент/дата, заголовок панели, строки
`показатель|результат|ед.|референс` по колонкам, многостраничность через `rows_per_page`).
Текстовый слой кириллический (`china-s`), совместим с `reconstruct_pages`.

```python
def test_example(make_lab_pdf, tmp_path):
    p = tmp_path / "oak.pdf"
    make_lab_pdf(
        p,
        rows=[
            ("Гемоглобин", "13.7", "г/дл", "11.7-15.5"),
            ("Лейкоциты", "5.15", "×10⁹/л", "4.5-11.0"),
            ("СОЭ", "9", "мм/ч", "<20"),
        ],
        lab="ИНВИТРО",
        title="Общий анализ крови",
        rows_per_page=20,   # воспроизводит многостраничный бланк (см. итер.12–13)
    )
```

Тесты билдера: `tests/test_make_lab_pdf.py`. Следующий шаг расширения — пресеты реальных
панелей (ОАК 21 строка, биохимия) из ФСЛИ для генерации эталонного набора.

## D. HITL-сбор — долгосрочный эталон

По стратегии отчёта (раздел 8.3): каждый обработанный и подтверждённый врачом/оператором
документ (анонимизированно) сохраняется в локальную базу. Цель — **эталонный набор из 100
размеченных вручную документов от 5–7 крупнейших российских лабораторий**, на котором
считаются метрики до и после каждого изменения pipeline. К 3 месяцу — 1500–3000 размеченных
пар для будущего LoRA-fine-tune.

## Рекомендованный приоритет для botkin

1. **Сейчас:** полу-синтетический РФ-корпус (C, `make_lab_pdf` + ФСЛИ) для русской
   терминологии и детерминированных регресс-тестов; + CMDD/Xue-238 (B) для проверки OCR/VLM
   на реальных фото/сканах (CBC-структура совпадает).
2. **Средне:** регистрация в SibMED (A), выгрузка словарей параметров/единиц как ground-truth
   справочник для нормализатора.
3. **Долго:** HITL-эталон из 100 реальных РФ-документов (D).
