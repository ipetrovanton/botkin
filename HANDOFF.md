# Handoff: контекст и промпт для агента без локальной LLM

Этот файл — самодостаточный ввод для агента (например, Claude на сервере), у которого **нет
локальной Ollama/GPU**. Он объясняет проект, что уже сделано, какие сложности открыты и как
продолжать работу без возможности гонять реальную модель.

---

## Промпт для агента (копировать целиком)

> Ты продолжаешь работу над проектом `botkin` — сервис распознаёт медицинские документы
> (бланки анализов, заключения врачей) локальной vision-моделью Ollama (`qwen3-vl:8b-instruct`)
> и извлекает структурированные показатели. Пайплайн: **classify** (тип документа) →
> **extract** (показатели) → normalize → persist.
>
> **ВАЖНОЕ ОГРАНИЧЕНИЕ ТВОЕГО ОКРУЖЕНИЯ:** у тебя НЕТ локальной Ollama и GPU. Значит ты
> **не можешь** запускать e2e-тесты, дёргающие реальную модель (маркер `llm`). Они и так
> авто-скипаются без Ollama. Работай так:
> - Прогоняй только unit-тесты: `uv run pytest -m "not llm"` (сейчас проходит **313 passed**).
> - Логику, зависящую от LLM, проверяй через **моки** (см. `tests/test_text_layer_extract.py`,
>   `tests/test_androflor_parser.py` — там `_call_text`, `_call_image_ocr`, `_vlm_extract_attempt`
>   подменяются лямбдами/фейками). Любую правку в `extract.py`/`classify.py` закрывай
>   unit-тестом с моком, не реальным вызовом.
> - НЕ добавляй в тесты реальные сетевые вызовы к Ollama. НЕ меняй `pyproject.toml`
>   `addopts = "-m 'not llm'"` — это защита CI без GPU.
> - `ruff check src/ tests/` должен быть чист. Менеджер пакетов — `uv` (есть `uv.lock`), только он;
>   зависимости ставятся `uv sync`.
> - Если правка требует боевой проверки на реальной модели — не выполняй её вслепую, а опиши
>   в ответе, что нужно прогнать оператору с GPU (команда: `uv run pytest -m llm -s`), и
>   подготовь всё так, чтобы он запустил одной командой.
>
> **ВХОДНЫХ ДОКУМЕНТОВ НЕТ В РЕПО.** Реальные PDF/фото (`tests/fixtures/documents/samples/*.pdf|jpg`)
> не версионируются (ПДн, см. `.gitignore`). У тебя есть только эталонная разметка рядом
> (`*.expected.json`, 35 файлов) — из неё видно ожидаемые значения/единицы/референсы. Сырой
> OCR-текст проблемных строк, где это нужно, приведён прямо в разделе «Открытый техдолг» ниже.
> Не пытайся открыть `sample_*.pdf` — их нет; опирайся на эти примеры и `*.expected.json`.
>
> Правила проекта — в `AGENTS.md` и `CLAUDE.md` (они в репо). Файлы `.windsurf/rules/` и
> `~/.config` НЕ в репозитории — не рассчитывай на них. Ключевое из них: отвечай по-русски;
> TDD (тест → фикс); не пиши объяснения в комментариях кода — только в ответе; перед правкой
> читай соседний код и следуй его конвенциям.
>
> Открытые задачи и известные сложности — ниже в этом файле, раздел «Открытый техдолг».
> Полная история расследований — `habr/2026-06-27--ollama-speed-optimization.md` (эта итерация)
> и `habr/lab-results-journal.md` (предыдущие). Снимок «где мы сейчас» — `.remember/remember.md`.

## Что уже сделано (кратко)

Оптимизация скорости и точности OCR-пайплайна. Итог последнего полного e2e-прогона см. в
`TEST_RESULTS.md`. Ключевые изменения относительно коммита `9537180`:

- **config.json:** `num_predict` 16384→4096, `num_ctx` 16384→8192, `temperature` 0.0 (extract) /
  0.1 (classify, ключ `classify_temperature`), `repeat_penalty` 1.1.
- **classify.py:** детерминированный корректор типа по заголовку — если `title` содержит
  «общий анализ»/«анализ крови»/… → принудительно `analysis` (чинит флуктуацию VLM на
  sample_011, где ОАК иногда классифицировался как `doctor_report`).
- **extract.py:**
  - Adaptive fallback против пустого ответа XGrammar на **картиночном** пути
    (`_vlm_extract_with_retry`) и на **текстовом** (`_structure_text`, бюджет
    `_TEXT_EMPTY_RETRIES=2`). Это устранило плавающие FAIL (sample_001 был 3/6 → стал 6/6).
  - Декомпозиция `_extract_once` на `_vlm_extract_with_retry` + `_supplement_with_vlm`.
  - Удалён мёртвый и сломанный «гибридный fallback» (ссылался на неимпортированные
    константы, ветка была недостижима).
- **text_layer.py:** объединены `_parse_text_line` и `_parse_text_line_all` через общий
  `_parse_first_result`; multi-result парсинг склеенных строк; склейка тысяч только для целых
  (`_INT_ONLY_RE`), чтобы «5.5 5» не превращалось в «5.55».
- **warmup (client.py):** `warmup()` грузит модель(и) в VRAM на старте (bot `main()`, API
  `lifespan`) фоном — первый документ не платит холодный старт ~100–120s. Best-effort, без GPU
  тестируется моком `urlopen` (см. `tests/test_client_hygiene.py`).

## Как проверять без GPU

```bash
uv sync                          # поставить зависимости из uv.lock
uv run pytest -m "not llm"       # 613+ passed — основной способ проверки
uv run ruff check src/ tests/    # линт
```

Тесты, дёргающие реальную модель, помечены `@pytest.mark.llm` (`test_e2e_llm.py`, `test_e2e_reasoning.py`)
и без Ollama авто-скипаются. Их запускает только оператор с GPU (`uv run pytest -m llm -s`) — тебе они недоступны.

## Открытый техдолг (кандидаты на фикс)

1. **[ИСПРАВЛЕНО 2026-07-02] Мусорная строка от `completeness_guard`.** На строке
   `Антиген аденогенных раков Са 125 8.13 Ед/мл < 35 ...` парсер читал «125» (часть имени
   «Ca 125») как значение и плодил фантом `Антиген аденогенных раков Са = 125.0`. Фикс:
   `_is_name_embedded_number` в `text_layer.py` — число считается частью имени, если за ним
   идёт ЕЩЁ число (настоящее значение), а следом единица/оператор (а не тире-диапазон и не
   число). Регрессионные тесты: `test_parse_text_line_number_in_analyte_name_is_not_value`,
   `test_parse_text_line_all_keeps_ph_second_value_after_range`.

2. **Остаточная нестабильность (крайне редкая).** Даже с ретраем возможен двойной пустой
   ответ модели. Сейчас бюджет `_TEXT_EMPTY_RETRIES=2` закрывает наблюдаемые случаи (6/6).
   Если оператор сообщит о новых плавающих FAIL — рассмотреть fallback с текстового пути на
   картиночный (`_extract_once`), когда `_structure_text` вернул 0 строк на всех попытках.
   Проверять только на GPU.

3. **Единицы/референсы «прилипают» к соседним токенам.** На sample_001 HE4 извлекается с
   `unit='пмоль/л Cobas 6000 человека НЕ4 в крови'` и `ref_high=140` вместо `70`. Причина —
   бланк даёт ДВА порога на одной физической строке, а имя разорвано значением. Сырой текст
   слоя (можешь гонять `_parse_text_line`/`completeness_guard` на нём как на чистой функции,
   GPU не нужен):
   `Секреторный белок эпидидимиса <70 - пременопауза. 47.14 пмоль/л Cobas 6000 человека НЕ4 в крови <140 - постменопауза`
   Ожидание (`sample_001.expected.json`): `value=47.14, unit='пмоль/л', ref_op='<', ref_high=70`.
   Нужно: (а) не втягивать «Cobas 6000 …» в unit; (б) при двух порогах брать первый (пременопауза).
   Правка в `_extract_unit_ref`/`_parse_first_result` (`text_layer.py`) — тест без мока и без GPU.
   Часть «прилипания хвоста» может исходить от VLM — финально подтверждать на GPU
   (`uv run pytest -m llm -s -k sample_001`).

4. **TEXT_MODEL.** Сейчас = `qwen3-vl:8b-instruct` (та же VLM). Отдельная `qwen3:8b` в
   end-to-end оказалась хуже (3/6 против 6/6): отдаёт непустой, но неверный результат.
   Не переключать без полного e2e на GPU.

## Где что лежит

- Пайплайн: `src/botkin/pipeline/orchestrator.py` (classify → extract → persist).
- LLM-вызовы: `src/botkin/llm/{classify,extract,client,prompts}.py`.
- Детерминированный разбор: `src/botkin/parsing/{text_layer,scalars,rows,harvester,androflor,sibr}.py`.
- e2e-тест и сверка: `tests/test_e2e_llm.py` (PASS/FAIL по `missing` эталонным значениям).
- Бенч-обвязка: `scripts/bench/` (`bench_models.py` гоняет e2e и парсит сводку;
  `bench_compare.py` сравнивает с baseline). Требует GPU.
- История и обоснования: `habr/2026-06-27--ollama-speed-optimization.md`.
