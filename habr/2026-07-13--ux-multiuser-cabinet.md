# Многопользовательский кабинет: роли, верификация распознавания, MinIO, формы пациента и «рекомендации дня»

> Дата начала: 2026-07-13 20:56
> Стек: Python 3.12, FastAPI, SQLite (+sqlite-vec), Alpine.js SPA, Ollama (qwen3-vl, bge-m3), aiogram

## Постановка

Пользователь попросил большой UX-апгрейд веб-кабинета: разделение по пользователям с ролью
администратора (CRUD пользователей и анализов); подтверждение/корректировка распознанных
данных при загрузке (+ручное добавление показателей/лекарств/рекомендаций); хранилище
оригиналов документов (S3) с удалением/заменой/версионированием и валидацией изменений;
формы профиля тела (возраст, пол, вес, группа крови и т.д.), жалоб в свободной форме,
текущих препаратов; настройка частоты синка Garmin; «рекомендации дня» с учётом погоды,
геомагнитных бурь и (по настоянию пользователя) гороскопа. Все данные форм должны влиять
на RAG-рекомендации. Плюс: дать локальным моделям веб-доступ с пополнением RAG-базы
результатами, и бенчмарк нескольких эмбеддинг-моделей (компактных и максимально больших).

Критерий успеха: все 7 этапов реализованы, тесты зелёные, кабинет работает локально.

## Контекст и ограничения

- Окружение: macOS (разработка), прод-схема Windows+WSL2+Ollama; Python 3.12, uv.
- До начала: однопользовательский-по-факту кабинет, идентификация — спуфабельный
  заголовок `X-Telegram-User-Id`; файлы на локальном диске `data/sources/{user_id}/`;
  ролей нет; RAG на bge-m3 (1024-dim, sqlite-vec); health-sync Garmin/Strava уже есть.
- Ограничения: всё локально (без облака), демо-уровень безопасности — по явному выбору
  пользователя в интервью.

## Интервью (решения пользователя)

1. Аутентификация: **демо-уровень** — заголовок остаётся, добавляем роли и экран выбора.
2. Хранилище: **MinIO** (настоящий S3-API локально в Docker), а не абстракция над диском.
3. Астрология: **как развлечение** — отдельный опциональный блок с дисклеймером,
   «не влияет на медицинские выводы». От влияния на рекомендации отговорил.
4. Объём: **все 7 этапов в одной ветке**, коммит на этап.

## План

1. Роли (admin/user) + админ-API + экран администратора в SPA.
2. Верификация распознанного: статус review, форма редактирования показателей/лекарств/
   рекомендаций, ручное добавление.
3. MinIO-хранилище оригиналов: версии, удаление/замена, валидация изменений.
4. Формы: профиль тела, жалобы, текущие препараты; учёт в контексте RAG-рекомендаций.
5. Настройка частоты обновления Garmin в кабинете.
6. «Рекомендации дня»: Open-Meteo (погода/давление), NOAA SWPC (Kp-индекс),
   гороскоп отдельным развлекательным блоком.
7. Веб-доступ моделей с пополнением RAG + бенчмарк эмбеддинг-моделей.
