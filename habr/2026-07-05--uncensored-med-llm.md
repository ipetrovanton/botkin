# Локальные LLM без цензуры для разбора анализов: 5 свежих моделей, RAG из PubMed и живой веб

> Дата начала: 2026-07-05 20:55
> Стек: Python 3.12, uv, Ollama (WSL2), sqlite-vec, bge-m3, httpx, PubMed E-utilities, DuckDuckGo Lite

## Постановка

Задача пользователя: изучить доступные локальные нейросети **без цензуры** (uncensored/abliterated),
пригодные для медицины и русского языка; выбрать до 5 и установить локально; прогнать их через RAG,
построенный на реальных тестовых анализах пациента; проанализировать выводы и рекомендации;
дополнительно — дать моделям **доступ в интернет** за справкой и подключить **RAG с медицинскими
исследованиями** (PubMed) с возможностью автономного обновления. Результат оформить фактурой для Хабра.

Критерий успеха: 5 свежих uncensored-моделей установлены; работает единый прогон
«вопрос пациента → RAG-контекст (+ свежие статьи + веб) → ответ модели»; собраны и
проанализированы ответы; инфраструктура research-RAG обновляется одной командой.

## Контекст и ограничения

- Железо: **RTX 3080 Laptop 16GB VRAM + 48GB RAM**. Практический потолок весов ≈ 55GB
  (VRAM + оффлоад в RAM), скорость некритична.
- В проекте уже был RAG: bge-m3 (1024-dim) через Ollama `/api/embed`, векторное хранилище на
  `sqlite-vec` (таблицы `rag_chunks` + `rag_vectors`), ретривер и `recommend()` с контекстом
  из справочников ГРЛС/ФСЛИ, отклонений анализов и данных носимых устройств.
- Тестовые данные: `user_id=1` (demo telegram 113521070) — 318 показателей, 9 заключений;
  среди отклонений лимфоциты 40% (норма 19–37), моноциты 11.7% (норма 3–11), базофилы.
- Ограничение: ответы моделей — на русском; модель не назначает лечение (ассистент, не врач).

## План

1. Ресёрч рейтингов uncensored-моделей, проверка реальных тегов Ollama и требований по железу.
2. Выбор 5 **свежайших** моделей (Qwen3.6, GLM-4.7-Flash, медицинская, reasoning) и установка.
3. Медицинский research-RAG из PubMed + автономное обновление (source="research").
4. Живой веб-доступ моделей (веб-поиск + PubMed) как augmentation контекста.
5. Прогон 5 моделей × вопросы × {без веба / с вебом}, сбор ответов и метрик.
6. Анализ, графики, оформление фактуры.

## Ход работы

### Шаг 1: Ресёрч и выбор моделей (с проверкой каждого тега)

Первый заход по «топам» дал годовалые abliterated-модели (Qwen3, DeepSeek-R1, Gemma3). Пользователь
поправил: нужны **самые свежие** (Qwen3.6/3.7, GLM Heretic) и подключить GLM. Второй ресёрч + ручная
проверка страниц `ollama.com/.../tags` (важно: субагент несколько раз выдумывал теги — доверяем только
тому, что реально открылось):

| Модель | Тег | Размер | Свежесть | Заметка |
|---|---|---|---|---|
| Qwen3.6-abliterated 27B | `huihui_ai/Qwen3.6-abliterated:27b` | 17GB | 2 мес | dense, лучший русский |
| Qwen3.6-abliterated 35B MoE | `huihui_ai/Qwen3.6-abliterated:35b-a3b` | 24GB | 2 мес | 36B/3B active |
| GLM-4.7-Flash abliterated | `huihui_ai/glm-4.7-flash-abliterated:q4_K` | 19GB | 5 мес | 30B-класс, без цензуры |
| JOSIEFIED-Qwen3 8B Health | `goekdenizguelmez/JOSIEFIED-Qwen3:8b-health-q6_k` | 6.7GB | — | медицинская, uncensored |
| DeepSeek-R1 32B uncensored | `richardyoung/deepseek-r1-32b-uncensored` | 19GB | 7 мес | Heretic, reasoning `<think>` |
| qwen3:8b (бейслайн) | `qwen3:8b` | 5.2GB | — | цензурный контроль |

Честное ограничение: **GLM-4.6/5.2 и GLM-4.5-Air не влезают** в 16GB VRAM + 48GB RAM даже в q4
(176–350B параметров → 70–400GB). «GLM-4.7 Flash Heretic» как отдельный тег есть только в виде GGUF
на HuggingFace; в Ollama доступен эквивалент `glm-4.7-flash-abliterated` (тоже декенсур, 30B).

### Шаг 2: Research-RAG из PubMed + автономное обновление

Добавлен источник `source="research"` в тот же векторный индекс. Модуль `botkin/rag/research.py`
тянет свежие абстракты через PubMed E-utilities (esearch по теме, sort=date → efetch XML), парсит
`xml.etree`, складывает чанки идемпотентно по PMID. Скрипт `scripts/update_medical_research.py`
обновляет базу одной командой (пригоден для планировщика ОС). Первый прогон: **79 публикаций** по
6 темам (лимфоцитоз, моноцитоз, базофилия, отклонения ОАК, ЦСЖ, вирусные инфекции).

Ключевое: `retriever.search` в `recommend()` вызывается без фильтра источников, поэтому research-чанки
подхватываются автоматически — правки в поиске не понадобились.

### Шаг 3: Живой веб-доступ моделей

Выбран подход «augmentation контекста» (а не tool-calling: uncensored-модели плохо держат tools).
`botkin/rag/websearch.py`: `web_search` (DuckDuckGo Lite) + `pubmed_search` (живой PubMed),
результаты подмешиваются в промпт блоком «СВЕЖИЕ ИСТОЧНИКИ ИЗ ИНТЕРНЕТА». Флаг `use_web` в
`recommend()` (по умолчанию из `RAG_WEB_ENABLED`).

### Шаг 4: Дымовой тест на qwen3:8b — пайплайн работает

`recommend(use_web=True)` на вопрос про лимфоциты/моноциты: `web_used=True`, 45.7s, в контексте —
research + analytes + drugs. Модель **процитировала конкретные находки из проиндексированных
абстрактов** (Listeria-менингоэнцефалит с лимфоцитарным плеоцитозом ЦСЖ; GFAP-ассоциированная
астроцитопатия с моноцитозом/лимфоцитозом ЦСЖ). То есть опора не только на «вшитые» знания, но и на
свежие статьи — ровно цель задачи.

## Архитектурные решения

### Решение: выбор 5 моделей

- **Альтернативы:** medical-специализированные с цензурой (Baichuan-M2, MedGemma, Meditron) —
  отброшены (требование «строго без цензуры»); полные GLM-4.6/5.2/Air — не влезают по железу.
- **Выбрано:** свежайшие abliterated Qwen3.6 (dense+MoE) + GLM-4.7-Flash abliterated + медицинская
  JOSIEFIED-health + reasoning DeepSeek-R1 (Heretic). Критерии: свежесть, влезаемость в 55GB,
  русский, разнообразие семейств/подходов для контраста в статье.
- **Компромисс:** 27B/32B частично оффлоадятся в RAM → медленно; ~85GB загрузки.
- **Когда пересмотреть:** при OOM/ <2 tok/s заменить крупные на кванты поменьше.

### Решение: research как источник в общем векторном индексе

- **Альтернативы:** отдельная БД/индекс под исследования — лишняя связность и дубль инфраструктуры.
- **Выбрано:** ещё один `source` в существующем `sqlite-vec` индексе. Ретривер и `recommend()`
  подхватывают его без изменений.
- **Компромисс:** CHECK-ограничение `rag_chunks.source` пришлось расширить (миграция с
  пересозданием таблицы, id сохраняются — иначе осиротеют вектора).
- **Когда пересмотреть:** если корпус исследований вырастет до сотен тысяч чанков и захочется
  отдельного жизненного цикла/чистки — вынести в свой индекс.

### Решение: веб-доступ через augmentation, а не tool-calling

- **Альтернативы:** агентный tool-calling (модель сама зовёт поиск) — но uncensored-модели
  нестабильны в tools.
- **Выбрано:** заранее ищем за модель (веб + PubMed) и кладём в контекст. Работает одинаково на всех.
- **Компромисс:** модель не управляет, что искать; ищем по исходному вопросу.
- **Когда пересмотреть:** если возьмём модель с надёжным tool-calling — дать ей поиск как инструмент.

## Сложности

### Сложность: кодировка вывода Windows (cp1251) рушила кириллицу

- **Симптом:** скрипты падали/молча теряли кириллические строки при выводе.
- **Решение:** `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8` для всех прогонов.
- **Урок:** на Windows-хосте с русским выводом форсировать UTF-8 обязательно.

### Сложность: CHECK-ограничение source не пускало 'research'

- **Симптом:** `sqlite3.IntegrityError: CHECK constraint failed: source IN ('drugs','analytes','health')`
  на вставке после успешного скачивания и эмбеддинга 79 статей.
- **Решение:** расширил CHECK в `schema.sql` + миграция `_migrate_rag_chunks_schema` с пересозданием
  таблицы и сохранением `id` (связь с `rag_vectors`).
- **Урок:** менять CHECK в SQLite = пересоздавать таблицу; для vec0-связей беречь `id`.

### Сложность: DuckDuckGo html-endpoint отвечает 202 (антибот)

- **Симптом:** после нескольких запросов `html.duckduckgo.com/html/` → 202 и пустая выдача.
- **Решение:** перешёл на `lite.duckduckgo.com/lite/` — прямые URL и заголовки, стабильно 200.
- **Урок:** для дешёвого веб-поиска Lite-версия DDG надёжнее html-версии.
